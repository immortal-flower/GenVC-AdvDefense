# GVCC 码流可靠性：论文主线与正式实验协议

## 1. 论文只回答一个问题

生成式视频码流中的等量错误是否具有稳定的“生成步骤 × 潜在时间位置”风险结构；在不知道测试视频事后热点的条件下，能否利用发送端可见的码流语法，以固定传输预算降低平均与尾部重建损失？

这一定义把工作限定为**生成式视频码流的结构化风险与可靠传输**。组合数索引、通用分组 FEC、完整网络协议和攻击算法均作为工具或基线，不单独宣称贡献。

## 2. 当前证据能支持什么

1. Jockey GOP0 的 17×9 扫描表明，16 个符号错误的影响高度不均匀，显著区域集中于早期 SDE 步骤的少数潜在时间位置。
2. 在 3 个攻击掩码种子下，Jockey GOP0 的三个候选坐标分别造成约 2.04、1.90 和 1.26 dB 平均 PSNR 下降；同一步骤或同一位置的对照点接近 0。
3. 固定坐标在 Beauty GOP0 和 Jockey GOP1 仍产生约 0.52–1.14 dB 下降，但强度随内容和 GOP 改变。因此当前证据支持“存在可迁移的结构先验”，不支持“热点坐标恒定不变”。
4. 单个潜在位置的符号错误可影响多个输出帧。峰值通常位于其名义帧段附近，但传播范围具有内容依赖性。
5. Jockey GOP0 的 SDE1/位置3上，符号错误预算从 8 增至64时，PSNR下降由约0.09 dB增至5.18 dB；同一步骤的位置0对照仍基本稳定。

以上结果目前属于探索性证据。旧结果缺少完整输入哈希、模型种子和配置指纹时，不应直接进入最终论文表格。

## 3. 明确不做的主张

- 不声称首次发现生成码本比特错误或组合排名错误传播。
- 不把重复码、XOR FEC、Cauchy RS 或交织本身当作算法创新。
- 不把已知测试集热点坐标的保护结果称为盲保护。
- 不把 `.tdcmr` 容器等同于包含参考帧、包头和信令在内的完整 GVCC 网络码流。
- 不把保守的 `SyntaxRecoverable` 判据称为真实解码成功率。

## 4. 正式实验的数据划分

### 开发集

- 只用于提出并冻结保护规则，例如 Jockey GOP0。
- 可以进行完整扫描、规则选择和预算调参。

### 验证集

- 用于一次性选择规则版本和信道强度，不再修改规则。
- 例如 Jockey GOP1。

### 测试集

- 不做热点扫描，不根据测试结果改变保护位置。
- 至少包含 5 个不同运动/纹理类型的视频，每个视频不少于 3 个 GOP。
- 每个正式结果记录视频片段哈希、模型种子、信道种子和完整参数指纹。

Beauty 已被反复查看，最终论文中宜作为验证样例而非唯一“未见测试序列”。

## 5. 主方法：冻结的结构化 UEP 规则

运行时只允许使用发送端天然知道的信息：字段类型、SDE步骤、潜在时间位置、GOP边界和码率设置。规则不得读取测试视频的攻击后质量或测试热力图。

建议比较以下策略，并保证**总发送字节数相同**：

| 策略 | 是否使用测试热点 | 作用 |
|---|---:|---|
| 无保护 | 否 | 质量下界 |
| 均等保护 EEP | 否 | 必须战胜的强基线 |
| 随机 UEP | 否 | 检验收益是否仅来自“集中冗余” |
| 仅早期步骤规则 | 否 | 检验步骤先验的独立贡献 |
| 冻结的步骤×位置规则 | 否 | 主方法；仅由开发集确定一次 |
| 测试集 oracle | 是 | 只作上界，不计入主方法 |

当前“保护三个完整坐标、每个64个符号”的实现不能等价代表 EEP。正式主实验前需要支持在相同384-bit冗余预算下，将保护符号均匀分布到全部153个步骤—位置单元。

## 6. 信道与评价指标

### 主信道

采用固定长度、可解析的符号位随机错误信道。发送端可读取码流语法，信道本身不知道敏感位置。至少报告三个强度，并对每个强度使用多个信道种子。

### 次信道

使用格式无关的整包丢失与强 RS/FEC 基线，用于说明应用边界，不作为论文的主要创新。包级实验必须将容器头、填充、校验、FEC奇偶包和参考数据纳入统一字节预算。

### 主指标

- GOP平均 PSNR下降和 LPIPS增加；
- 最差输出帧 PSNR下降；
- 每段视频的最差GOP；
- 失败概率，例如 PSNR下降超过1 dB或3 dB；
- 总发送字节、有效码率增量和运行时间；
- 置信区间，而不只报告均值。

## 7. 最小决胜实验

先跑一个小而严格的实验，决定主线是否成立：

- 2个未用于选点的视频 × 2个GOP；
- 5种策略：无保护、EEP、随机UEP、早期步骤、冻结联合规则；
- 3个信道强度 × 3个信道种子；
- 固定模型种子42，之后再补3个模型种子作为稳健性实验；
- 所有策略使用相同总传输字节。

若冻结联合规则在多数视频/GOP上显著优于EEP，并同时改善平均损失、最差帧和失败概率，再扩展到完整测试集。若只在开发内容上有效，应把论文收缩为“风险测量与传播分析”，而不是提出通用保护方法。

## 8. 实验推进顺序

1. 用证据审计脚本区分探索性结果与具备完整配置指纹的正式结果。
2. 实现“部分符号保护”，使EEP、随机UEP和结构化UEP能在同一冗余预算下比较。
3. 冻结开发集规则和三档信道强度，写入不可变配置文件。
4. 运行最小决胜实验，中途不按测试结果改规则。
5. 通过后扩充视频、GOP和模型种子，并补充尾部风险统计。
6. 最后才做包级RS、组合索引和更多防御组件的消融。

## 9. 运行记录要求

正式批处理统一加 `--formal_run --experiment_tag <tag>`。正式目录名和 `metrics.json` 中会包含内容派生的配置ID；只有ID完全一致的旧结果才能跳过。任何没有配置ID、模型种子或输入GOP哈希的结果均标记为探索性结果。
